# Active execution steering acceptance

Ticket #7, parent spec #1. The public host tool `subagent_steer({run, guidance})` queues original-task guidance for the owning session's active execution. Guidance is limited to 8,000 characters and eight pending items. Admission is serialized per execution; each record stores bounded accepted/consumed/pending/discarded counts and only the latest guidance ID/state/timestamps. Guidance text/history is absent from compact native rows.

Acceptance is durably persisted before the tool returns. Consumption means a committed UserEntry at a tool/turn boundary; neither count claims obedience. Public SDK passive write submissions are deliberate: an input submission with `whenBusy: steer` can start a new generation if the child becomes idle between inspection and admission. A passive write cannot start another task in that race. At a final boundary it can be inserted without another model turn; consumption therefore does not prove that a model read or obeyed it. An explicit follow-up is required for new completed-child work. Agent loadout, model, authority and original task remain frozen.

`test/pi-steering.test.ts` uses the installed real parent session, extension tools, SQLite child harness, controlled host shell boundary and a real workspace output file. The provider is deterministic and offline. Acceptance while the shell is blocked persists accepted1/consumed0 without aborting the shell; after release the child sees guidance, writes `revised evidence`, and retains the original task and Agent definition. A host tool outside the frozen child allowlist remains unexecuted even when guidance requests it. Completed-child guidance is rejected with follow-up direction. A completion race causes only the original two child generations and one shell, never a new task. Queue overflow rejects the ninth pending item. Cancellation and session reload discard all eight pending items, persist pending0/consumed0/discarded8, and startup does not restart them. Ownership uses the existing session-scoped status check.

Red evidence: all original three host cases failed against ticket #6's implementation (outside-repo log `/tmp/pi-spec-1/ticket7-red.txt`); green: all four steering host cases pass. Full suite passes 159 tests; typecheck passes. The final added authority assertions also pass in the targeted host suite.

Unchanged native presentation was probed using `test/fixtures/tui-redesign-probe.py --scenario supervised`: 80-column dark regular and 120-column light fullscreen passed, including spinner, Ctrl+O, fullscreen mouse expansion, retained expansion during resize, and full sticky removal to the SDK baseline composer spacer. No UI layout or rendering geometry changed and no paid provider calls were made.
