# Explicit nonblocking supervision (#6)

`subagent({agent,task,nonblocking:true})` returns the persisted Run ID after ownership admission. Existing calls stay blocking. Detached calls have an independent abort controller and hold the live owning Pi runtime until completion or awaited shutdown. `subagent_status({run})`, `subagent_wait({run,waitSeconds?})` (default 60 seconds, bounded 0–3600), and `subagent_cancel({run})` enforce owner identity. Wait expiry or cancellation of the parent wait leaves child work live. The operator configures active capacity with `PI_SUBAGENT_MAX_ACTIVE` (default eight); admission returns busy immediately with no queue. Capacity includes all active phases and nested work, separately from batch and nesting limits. Terminal or safely paused execution releases the slot and workspace lease.

`test/pi-supervision.test.ts` exercises the installed Pi SDK through actual parent tool calls and retained session history. The parent completes three reasoning turns after start and a bounded wait expires. Child tools read an actual disposable file after return; a changed host permission hook denies the second access after an intervening parent turn. Exactly one side effect occurs. Durable retains two distinct tool IDs and one stable Run ID. Another host scenario exercises configured capacity, immediate busy/no queued work, blocking parent workspace writes, active cancellation and released capacity. Actual SDK `session.reload()` awaits child cancellation, marks the unfinished execution Interrupted, replaces the extension runtime, and allows inspection without restarting work.

Installed SDK limitation observed by the host fixture: the host hook IDs of late nested calls both become `detached-start/1` when parent settlement clears the original nested-call scope between child calls. Host permissions remain live, and the execution's Durable ledger IDs remain distinct (`durable-child-1`, `durable-child-2`); no tool is duplicated. The public `ctx.executeTool` API does not let an extension set detached nested call IDs. Detached usage/activity therefore belongs to the execution ledger, not the original start result's late nestedCalls record. The adapter preserves the public host permission path rather than invoking tool implementations directly. A supported host-scoped detached call identity API is a remaining SDK limitation.
