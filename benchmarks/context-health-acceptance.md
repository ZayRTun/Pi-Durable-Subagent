# Context health and explicit compaction acceptance (#9)

The installed host/session seam uses Pi 1.0.0 with a scripted provider. `test/pi-context.test.ts` checks projected context against the warning and fresh-conversation thresholds for 10,000 and 200,000 token windows, reports unavailable capacity honestly, and exercises applied, no-op, failed paid, and active-work-refused compaction. Successful and failed compaction receipts survive repeated retrieval without another operation or billed delta. Estimates derive from the public current-context projection and installed estimator, not cumulative billed usage. The public SDK subpath must be resolved with `import.meta.resolve`: the native extension loader rewrites static pi-ai subpaths through its compat alias, and CommonJS resolution does not support this import-only export.

`test/allowance-pause.test.ts` adds a paused → explicit compact → continue case through the host. It preserves the historical execution snapshot and excludes separately accounted compaction usage from the continuing execution's ledger. Removing the exclusion produced a 163,809-token continuation increment including the 98,501-token compaction, failing the regression. The corrected path passes. Each compact request gets an operation identity derived from the parent tool-call identity; replay retrieves the same receipt and does not report its usage twice.

A real installed Pi CLI was launched in a 100×40 fullscreen PTY with disposable definitions, storage, session directory, and the explicit `context-cli-acceptance.ts` fixture. Native status reported estimated context 16,747, capacity 10,000, warning threshold 8,000, fresh threshold 9,500, and no prior compaction. Explicit compaction reported an actual no-op with zero newly billed usage and preserved `Historical result.`. The fixture completed. Raw terminal and receipt evidence: `/var/folders/zk/6zwx9y7n6g5_3qgr3_62x0xr0000gn/T/durable-context-native-xhqps8wj/{terminal.ansi,events.jsonl}`. This is automated native-host evidence, not human visual sign-off. No native row geometry was changed.

All child harness openings disable SDK automatic compaction. Manual compaction checks both application idle eligibility and SDK unfinished tasks/submissions before enabling scheduling, acquires workspace and conversation leases, consumes per-session active capacity, and supports cancellation/owner shutdown. It confirms the terminal task receipt and actual summary write placement before reporting applied. Historical answers and authority remain intact. Approximate committed context excludes live partial output and possible next-request transformations; compaction makes no reasoning-quality promise.

Follow-up API for #10: `Runtime.inspect(id, {sessionId, models})` returns `Run.contextHealth`; `validateReuseDecision(health, reuse)` requires `reuse === true` when warning is set; `Runtime.compact` returns persisted `Run.compactions` with operation identity, actual outcome, error if any, and independently attributed new usage. Existing execution ledger accounting subtracts these separately attributed compaction operations. New follow-ups must additionally subtract the previous execution baseline when assigning their own identities.
